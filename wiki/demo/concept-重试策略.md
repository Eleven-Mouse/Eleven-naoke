# 重试策略设计口径

## 什么时候该重试

只重试**瞬时故障**：超时、连接重置、503。4xx 参数错误重试多少次都不会成功，直接失败上抛。

## 指数退避 + 抖动

- 间隔序列：`base * 2^n`（base=100ms，上限 5s）；
- 每次叠加全抖动（full jitter）：`random(0, min(cap, base * 2^n))`，避免失败方同步重试形成重试风暴；
- 重试次数默认 3 次，可被调用方覆盖。

## 重试的前提是幂等

写操作必须先确认幂等（幂等键 / 条件写 / 去重表），否则重试会把"没成功"变成"成功了两次"。读操作天然幂等，可直接重试。

## 重试预算

调用方为每个下游维护 10% 重试预算：当重试流量超过总请求的 10%，直接熔断新重试——防止下游已经过载时被重试流量压垮。

## 与超时的配合

单次请求超时 < 整体 deadline；重试后总耗时必须仍然 ≤ deadline，超了就不要发第三次。
